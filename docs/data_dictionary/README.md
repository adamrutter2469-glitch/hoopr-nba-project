# Data dictionary

Auto-generated by [`scripts/build_data_dictionary.R`](../../scripts/build_data_dictionary.R)
from the pipeline's **live parquet schemas**, not hand-typed - so it can't silently drift out
of sync with the real data the way a static document would. Re-run that script any time a
table's columns change:

```bash
Rscript scripts/build_data_dictionary.R
```

## Format

One CSV per table. Row 1 describes the table itself; every row after that describes one
column, in the table's actual column order.

| Column | Table row (row 1) | Column rows (row 2+) |
|---|---|---|
| `row_num` | `1` | position in the table, `2..n+1` |
| `name` | table name | column name |
| `description` | what the table is, high level | what the column holds |
| `logic` | `NA` | how it's derived - `NA` if pulled with no transformation |
| `sources` | core source tables | `;`-separated source column(s), or the raw API call |
| `dtype` | `NA` | column's actual type, read from the live data |
| `feature_family` | `NA` | tag for filtering - see below |
| `leakage_risk` | `NA` | whether it's safe to use predicting *that same game* - see below |

## `feature_family` values

`identifier`, `metadata`, `context` (rest/travel/home-away), `raw_actual` (this exact game's
actual result), `own_rolling`, `opponent_rolling`, `allowed`, `opponent_allowed`, `matchup`,
`reference` (player/team master data), `unclassified` (not recognized - filled in with a
`NEEDS REVIEW` placeholder instead of a guess; grep for it before trusting a table fully).

## `leakage_risk` values

This is the same distinction that `models/train_rebounds_model.R`'s predictor allow-list is
built around: `safe` columns are fixed before tip-off; `UNSAFE` columns are that exact game's
actual outcome and must never be used to predict that same game (they're fine as a label/
target, or for post-game analysis). `NA` means unclassified - check the column yourself.
